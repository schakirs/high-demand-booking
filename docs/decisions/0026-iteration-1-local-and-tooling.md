# 0026 — Iteration 1 local and in CI only; tooling; one ADR per decision

- **Status**: Accepted
- **Date**: 2026-10-09 (date of the reference document; original decision date not recorded)
- **Related**: D-018, D-019, D-022

## Context

Iteration 1 must prove that holds are correct under concurrency; that proof does not need the
cloud. Tooling should be free and standard. Much of the code is generated by AI, so
formatting must be enforced mechanically. Decisions should be readable by an outside reader
(e.g. a recruiter).

## Options considered

1. **Deploy to the cloud from iteration 1** — realistic measurements early; cost and setup
   effort before the core is proven.
2. **Local and CI only.**
3. **Decisions kept only in the reference's log** — one place; hard to read and to link.
4. **One ADR file per decision.**

## Decision

Iteration 1 runs entirely locally and in CI. Tooling: k6 for load, Prometheus and Grafana for
local observability, google-java-format through Spotless enforced in CI. Decisions are
recorded as one ADR file per decision in `docs/decisions/`.

## Consequences

- Free, standard tools; stable formatting despite generated code; readable ADRs.
- No measurement in a cloud environment during iteration 1.
- More files to maintain.

## Revisit when

A cloud environment is planned, or local measurements cannot answer a question an iteration
must settle.
